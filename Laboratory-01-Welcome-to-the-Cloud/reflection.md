# Reflection

This laboratory activity was a good introduction to cloud computing because it allowed me to work directly with a Linux environment through KillerCoda. At first, working with the terminal felt a little unfamiliar because most of the tasks had to be done using commands instead of clicking graphical buttons.

One of the things I learned was how to create and manage a Linux user. I created my own user account, gave it sudo privileges, and logged in using that account. I also learned basic commands such as `whoami`, `pwd`, and `hostname`, which helped me understand the environment I was working in.

I also learned how to check the system information of a Linux machine. Commands such as `uname`, `lscpu`, `free`, and `df` made it possible to see information about the operating system, kernel, processor, memory, and storage. Before this activity, I did not pay much attention to these details, but I realized that system information is important when managing computer and cloud resources.

Another part that I found useful was creating the folder structure and Markdown files. It showed me that organizing files properly makes technical work easier to understand and maintain. The screenshots were also important because they served as evidence that I actually performed the activities.

The GitHub part was also meaningful to me because it introduced me to the idea of maintaining a professional technical portfolio. Instead of keeping my laboratory files only on my computer, I can organize them in one repository and continue adding future activities.

Overall, I learned that cloud computing is not only about deploying services. It also requires basic Linux knowledge, organization, documentation, and version control. I still need more practice with Linux and Git, but this first activity gave me a better starting point and made me more comfortable working with the command line.
